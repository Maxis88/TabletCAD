# Audyt TabletCAD — 2026-10-16

## Stan zweryfikowany

- Natywna aplikacja Android (Java + C++/JNI), bez WebView, `minSdk 34`.
- Biblioteki Open CASCADE 8.0.1 dla `arm64-v8a` ładują się na tablecie.
- Rdzeń tworzy i waliduje testową bryłę B-Rep oraz przechodzi techniczny zapis i
  ponowny odczyt STEP.
- Dotykowa kamera obsługuje orbitę w dwóch osiach, przesunięcie i skalowanie.
- Można wybrać płaszczyznę XY/XZ/YZ albo płaską ścianę bryły; kamera ustawia ją
  prostopadle do użytkownika.
- Szkic obsługuje linię, prostokąt i okrąg na aktywnej płaszczyźnie.
- Dokument `.tcad` przechowuje UUID encji, płaszczyznę, geometrię szkicu i
  parametry bryły. Autosave jest atomowy i tworzy kopię odzyskiwania.
- Na fizycznym tablecie potwierdzono odtworzenie szkicu oraz głębokości 44,40 mm
  po wymuszonym zatrzymaniu i zimnym uruchomieniu aplikacji.

## Mapa aktualnej architektury

| Warstwa | Implementacja | Stan |
|---|---|---|
| UI i gesty | `CadWorkspaceView` (Android Canvas) | działające MVP, monolit do podziału |
| Dokument | `CadProject`, `SketchPrimitive` | wersjonowany model początkowy |
| Trwałość | `ProjectRepository` | autosave, plik tymczasowy, `fsync`, backup |
| Geometria | `NativeCadEngine` + OCCT/JNI | bryła testowa i test STEP |
| Renderowanie | projekcja Java | nie renderuje jeszcze siatki z OCCT |
| Solver szkicu | brak | bloker modelowania parametrycznego |
| Historia cech | pojedyncze bazowe wyciągnięcie | brak zależności, rollback i undo/redo |
| I/O użytkownika | brak selektora dokumentów | STEP/STL/DXF niedostępne w UI |
| Rysunek techniczny | widoki demonstracyjne | brak asocjacyjnego arkusza |

## Najważniejsze luki i ryzyka

1. Widoczna bryła i selekcja nie pochodzą z topologii OCCT. Dalsze narzędzia nie
   mogą opierać się na obecnych indeksach ścian; potrzebne są stabilne referencje
   topologiczne i tessellacja rzeczywistego `TopoDS_Shape`.
2. `CadWorkspaceView` łączy dokument, narzędzia, kamerę i renderowanie. Przed
   rozbudową należy wydzielić kontroler dokumentu, renderer i stany narzędzi.
3. Szkic nie ma solvera więzów ani diagnostyki stopni swobody. Wyciągnięcie z
   dowolnego profilu byłoby bez tego kruche i nieprzewidywalne.
4. Dokument przechowuje obecnie jeden szkic i jedno wyciągnięcie. Nie ma grafu
   zależności, transakcji operacji, suppress/rollback ani bezpiecznej migracji
   nieznanej przyszłej wersji.
5. Importery plików nie mają jeszcze limitów zasobów ani izolacji błędów. Nie
   należy wystawiać ich w UI przed walidacją, raportowaniem postępu i anulowaniem.
6. Przycisk eksportu nie może być uznany za funkcję produktu, dopóki nie otwiera
   systemowego wyboru pliku i nie zapisuje zweryfikowanego STEP/STL/DXF.

## Kolejność implementacji

1. Model dokumentu wielu szkiców i cech, komendy oraz undo/redo.
2. Tessellacja OCCT, bufor siatki do Javy/OpenGL ES i selekcja rzeczywistej
   topologii.
3. Solver szkicu z więzami, wymiarami sterującymi i raportem stopni swobody.
4. Wyciągnięcie profilu z podglądem na żywo oraz operacjami join/cut/intersect.
5. Zaokrąglenie, faza, otwór i szyk na rzeczywistych referencjach topologicznych.
6. Android Storage Access Framework i kompletne importy/eksporty STEP/STL/DXF.
7. Asocjacyjny arkusz ISO/EU, PDF i druk Android.

Każdy etap wymaga testu jednostkowego warstwy dokumentu/geometrii, testu plików
referencyjnych, instalacji APK oraz próby dotykowej na fizycznym tablecie.
